# AdCrew: концепция креативного производства

Цель — сократить время от брифа до принятого креатива и сделать видимыми причины задержек, стоимость итераций и загрузку команды. Основной объект — задача на производство; файлы, версии, правки, участники и AI-расходы связаны с ней.

## Пользователи и рабочий цикл

- Покупатель описывает оффер, GEO, формат, объём, срок и критерии результата; проверяет сдачу и принимает работу либо оставляет конкретные правки.
- Креативщик берёт или получает задачу, загружает результаты, учитывает AI-кредиты, отвечает на комментарии и сдаёт следующую версию.
- Руководитель распределяет задачи, проверяет загрузку, сроки, качество приёмки и бюджет производства.

Пять этапов: **Новые → В работе → На проверке → Правки → Готово**. Возврат на правки сохраняет предыдущую сдачу и её замечания. Принятие доступно покупателю задачи, назначение — руководителю. Интерфейс показывает действия по роли и текущему этапу.

## Структура и взаимодействие разделов

| Раздел | Задача пользователя | Связь с остальным сервисом |
| --- | --- | --- |
| Производство | Управлять текущими задачами | Канбан, список, календарь дедлайнов, загрузка исполнителей, архив принятых работ используют один набор задач и фильтры |
| Карточка задачи | Принять решение, не теряя контекст | Справа открываются превью, сроки, участники, версии, обсуждение, чек-лист, AI-кредиты и действия; полная страница доступна по прямой ссылке |
| Шаблоны ТЗ | Быстро запустить похожую задачу | Сохранение брифа, повторный запуск с проверкой нового дедлайна |
| Уведомления | Видеть изменения, требующие реакции | Переход к соответствующей задаче, упоминания и уведомления по срокам |
| Аналитика | Оценивать результат производства | Сроки, цикл, доля приёмки с первого раза, правки, количество материалов; данные привязаны к сдачам и принятию |
| Команда | Понимать состав и загрузку | Роли, назначение на задачу, создание участника, открытые и завершённые задачи |
| AI-расходы | Считать стоимость производства | Кредиты по сервисам и версиям, тарифы в рублях, бюджет и остаток |
| История | Восстановить ход решений | Автор, время, действие и переход в задачу |
| Настройки и помощь | Управлять учётной записью и освоить процесс | Переключение темы, навигация, описание рабочего цикла |

## Дизайн и UX

Тёмная тема: графитовые поверхности, фиолетовый акцент, сдержанное разделение уровней. Светлая: светлый фон, белые карточки, тот же акцент и семантика статусов. Компоненты, отступы, типографика и действия совпадают в двух темах.

Карточки показывают реальный креатив, если у задачи есть обложка; задачи без файлов остаются компактными. В приоритете читаемость названия, дедлайн и исполнитель. Изображение не подменяет формат файла или статус. Выбранная карточка связана с правой панелью и выделяется контуром.

Быстрые фильтры: все, мои, сегодня, просроченные, оффер, GEO, формат, исполнитель. Дополнительные — приоритет и этап. Поиск, сброс и численность помогают понять, почему задача скрыта. На узком экране доска прокручивается внутри своей области, панель открывается поверх неё; Escape закрывает панель и возвращает фокус.

## Дополнительные функции и их польза

Уже реализованы в интерактивном прототипе:

1. **Несколько представлений одних данных.** Канбан — для движения задач, список — для быстрого обзора, календарь — для дедлайнов, загрузка — для распределения работы, архив — для принятых результатов.
2. **Проверка и обсуждение в правой панели.** Превью, история версий, скачивание, комментарии к раунду и чек-лист доступны без ухода с доски. Ссылка на задачу копируется для передачи контекста.
3. **Повторные запуски и шаблоны брифов.** Снижают объём ручного ввода и риск потерять требования.
4. **Показатели рядом с работой.** Материалы за семь дней, средний полный цикл, среднее число правок и доля приёмки с первого раза. Изменения считаются относительно предыдущих семи дней. Пустая выборка не превращается в вымышленную эффективность.
5. **Расходы по версиям.** Позволяют понять цену правок и сервисы, создающие основной расход, вместо одного общего числа кредитов.
6. **Права и сохранность.** Разделение ролей, проверка конфликтующих изменений, сохранение комментариев, версий и чек-листа после перезагрузки.

Следующий этап — предложения, пока не реализованные:

| Функция | Польза | Как проверить эффект |
| --- | --- | --- |
| Нормативы загрузки по сложности | Назначать работу по доступной мощности, а не только числу задач | Меньше просрочек при сопоставимом объёме |
| Комментарии по таймкоду видео | Связать замечание с конкретным кадром | Меньше повторных уточнений и раундов |
| Автопроверка сдачи | Проверять разрешение, длительность, пропорции и обязательные файлы до ревью | Выше доля приёмки с первого раза |
| Библиотека принятых креативов | Повторно использовать материалы и находить удачные форматы по офферу и GEO | Короче время запуска похожих задач |
| Результаты рекламы у версии | Сопоставлять CTR, CPA и расходы на производство с конкретным вариантом | Быстрее находить полезные креативные гипотезы |
| Telegram и облачные файлы | Получать адресные уведомления и работать с крупными исходниками | Меньше пропущенных дедлайнов и ручных переносов |

## Границы прототипа и развитие

GitHub Pages — интерактивный прототип: данные хранятся в IndexedDB конкретного браузера, работа вкладок синхронизируется. Общего межустройственного пространства, внешних уведомлений и подключения рекламных кабинетов в этой версии нет. Серверная сборка проекта имеет отдельный путь хранения и API; для командного запуска потребуются развёртывание сервера, общее файловое хранилище, управление пользователями и резервное копирование.

Критерий успеха следующего пилота: команда проводит полный реальный цикл от нового брифа до принятия, не дублируя историю правок в сторонних чатах; руководитель видит очередь ревью, просрочки и стоимость итераций в одном месте.
